# User Stories
## Introduction
In order to better understand what the user needs and why and how the webapp should behave (without going in technical deatils), user stories provide this kind of short and simple description told from the perspective of the end user (in our case, external non-technical users).

Since there is a standard Agile format, this is what it is going to be used throughtout this document:

As a **type of user**,
I want **a certain goal**,
So that **some benefit or reason**.

## Main User Stories
In our cases, we can define some main user stories, such as:

- As a **movie lover**, I want **to select a few movies I've enjoyed**, so that **I can get recommendations that match my taste**.

- As a **casual user**, I want **to receive a list of recommended movies based on my input**, so that **I can discover new titles I might enjoy**.

- As a **user**, I want **to modify my selected movies**, so that **I can refine the recommendations I receive**.

- As a **user**, I want **to search for specific movies in a searchable list**, so that **I can easily find the ones I liked**.
