Feature Requirements: User Flow & Functionality

After discussing with the team, I’ve outlined the core features the site must include:
1. Dynamic Movie Search Input
    + A text box where users can input reference films for recommendations.
    + As the user types, a dropdown displays matching movies (poster + title), with substring search (e.g., typing "Start" suggests Star Wars, Battlestar Galactica, or Star Trek).

2. Movie Selection & Validation
    + Users can add a movie by:
        - Clicking an item from the dropdown.
        - Pressing Enter (auto-selects the top suggestion).
    + If the input is misspelled/inexact, the system suggests the closest matches.

3. Interactive Selection Panel
    + Selected movies appear in a scrollable right-side panel (poster + title).
    + Each entry includes a removal option (e.g., "−" button or trash icon) for corrections.

4. AI Recommendation Trigger
    + A button at the panel’s bottom triggers the recommendation model.
    + Disabled until 5+ films are selected to ensure valid inputs.

5. Results Page
    + Displays recommended films (poster + title).
    + Hover-over popup shows details (synopsis, genre, rating, etc.).

6. "View as Map" Feature
    + A toggle button plots films on a 2D KNN-based map, visualizing similarity clusters.

7. Persistent State & Navigation
    + Users can return to recommendations while retaining their original input list.
    + The right panel preserves the selection history for adjustments.

Technology Stack Decision: Choosing the Right Approach

After carefully evaluating our options for the website implementation, I weighed the advantages and limitations of each potential solution.

The Streamlit approach initially seemed appealing due to its Python-based framework, which would integrate seamlessly with our AI model and database. Its automated deployment system also promised quicker setup times. However, this solution ultimately proved too restrictive - the platform's limited dynamic capabilities would force us to compromise on several key features the team had prioritized.

The alternative of full customization using HTML, CSS, and JavaScript offers significantly more flexibility. While HTML may be nearly three decades old, its container-based structure remains intuitive and pairs perfectly with CSS for styling control. JavaScript will enable the dynamic functionality we need to meet modern web standards and implement all our planned features. The main drawback is the substantial development time required, but given our team's resource allocation and timeline, this tradeoff is acceptable.

Following thorough discussion with the team, we've decided to proceed with full customization. The benefits simply outweigh the challenges in our case. With proper task distribution among team members and the time we have available, we're confident in delivering a solid version of the site. I'm not promising perfection - unexpected hurdles may arise during development - but this approach gives us the best foundation.

With this decision made, my immediate next step is to begin translating our hand-drawn wireframes into an initial working prototype of the site structure.

Refining Version 1.0: Problem Solving and UI Enhancements

Before implementing new features, I focused on addressing existing issues in the interface while significantly improving the overall user experience. Here's a detailed breakdown of the challenges encountered and the solutions implemented:

Dropdown Positioning and Behavior
The initial implementation had the search dropdown appearing too high above the input field. Through CSS adjustments, I successfully repositioned it below the search bar. However, this revealed an unexpected visual artifact - a thin shadow line remained visible when the dropdown was hidden. After investigating, I traced this to the dropdown's transition properties in the JavaScript. By modifying the opacity and visibility handling in script.js, I achieved a clean appearance when closed while maintaining smooth animations when opened.

Dynamic Film Removal Functionality
The right-side panel lacked a way to remove selected films. Inspired by the theme toggle implementation, I added trash can icons next to each film entry. This required:
    +Creating event listeners for each removal button
    +Developing JavaScript functions to update both the frontend display
    +Implementing corresponding backend routes in Flask to maintain data consistency
    The solution maintains visual consistency with our dark/light theme system while providing clear user feedback during interactions.

Enhanced Input Handling
The original implementation only supported mouse selection from the dropdown. To improve accessibility, I completely overhauled the keyboard interaction system:
    +Arrow keys now navigate through dropdown options
    +Enter key selects the highlighted item (or the first result if none are highlighted)
    +Form submission is now prevented during search interactions
    The most challenging aspect was synchronizing the dropdown's scroll position with keyboard navigation. By implementing scrollIntoView() calls and managing focus states, I created a seamless keyboard navigation experience that matches mouse interactions.

Responsive Design Implementation
Transitioning from pixel-based to relative units (em, rem, %) required a systematic approach:
    +Established a base font size for consistent scaling
    +Converted all fixed dimensions to fluid units
    +Implemented CSS media queries for breakpoints
    This ensures proper rendering across devices while maintaining our design aesthetic.

Visual Improvements and Microinteractions
The search bar received special attention to create a modern, polished feel:
    +Integrated the search button within the input field
    +Implemented a smooth color transition on hover
    +Added rounded corners matching the overall design language
    +Created an animated placeholder that moves to the input border
    
    For the film display panel, I:
    +Added proper spacing between items
    +Implemented scroll behavior for more than 5 films
    +Designed placeholder slots with "Add a movie" indicators
    +Ensured consistent styling across both color themes

Temporary Image Handling
Without access to the final film database, I:
    +Created a temporary image caching system
    +Implemented responsive image containers
    +Designed fallback states for missing artwork
    This maintains visual integrity during development while being ready for the final asset pipeline.

The current implementation successfully addresses all core requirements for the input page while establishing patterns we can extend to the results page. With these foundations in place, I'm now prepared to begin work on:
