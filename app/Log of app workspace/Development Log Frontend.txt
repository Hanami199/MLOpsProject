Feature Requirements: User Flow & Functionality

After discussing with the team, I’ve outlined the core features the site must include:
1. Dynamic Movie Search Input
    + A text box where users can input reference films for recommendations.
    + As the user types, a dropdown displays matching movies (poster + title), with substring search (e.g., typing "Start" suggests Star Wars, Battlestar Galactica, or Star Trek).

2. Movie Selection & Validation
    + Users can add a movie by:
        - Clicking an item from the dropdown.
        - Pressing Enter (auto-selects the top suggestion).
    + If the input is misspelled/inexact, the system suggests the closest matches.

3. Interactive Selection Panel
    + Selected movies appear in a scrollable right-side panel (poster + title).
    + Each entry includes a removal option (e.g., "−" button or trash icon) for corrections.

4. AI Recommendation Trigger
    + A button at the panel’s bottom triggers the recommendation model.
    + Disabled until 5+ films are selected to ensure valid inputs.

5. Results Page
    + Displays recommended films (poster + title).
    + Hover-over popup shows details (synopsis, genre, rating, etc.).

6. "View as Map" Feature
    + A toggle button plots films on a 2D KNN-based map, visualizing similarity clusters.

7. Persistent State & Navigation
    + Users can return to recommendations while retaining their original input list.
    + The right panel preserves the selection history for adjustments.

Technology Stack Decision: Choosing the Right Approach

After carefully evaluating our options for the website implementation, I weighed the advantages and limitations of each potential solution.

The Streamlit approach initially seemed appealing due to its Python-based framework, which would integrate seamlessly with our AI model and database. Its automated deployment system also promised quicker setup times. However, this solution ultimately proved too restrictive - the platform's limited dynamic capabilities would force us to compromise on several key features the team had prioritized.

The alternative of full customization using HTML, CSS, and JavaScript offers significantly more flexibility. While HTML may be nearly three decades old, its container-based structure remains intuitive and pairs perfectly with CSS for styling control. JavaScript will enable the dynamic functionality we need to meet modern web standards and implement all our planned features. The main drawback is the substantial development time required, but given our team's resource allocation and timeline, this tradeoff is acceptable.

Following thorough discussion with the team, we've decided to proceed with full customization. The benefits simply outweigh the challenges in our case. With proper task distribution among team members and the time we have available, we're confident in delivering a solid version of the site. I'm not promising perfection - unexpected hurdles may arise during development - but this approach gives us the best foundation.

With this decision made, my immediate next step is to begin translating our hand-drawn wireframes into an initial working prototype of the site structure.

Frontend Development Progress: Building Version 1.0

I've focused on implementing the first version of the film input interface, where users can search for movies and add them to the right-side selection panel. My development process began with establishing the basic HTML structure and CSS styling.

The first feature I implemented was the dark/light theme toggle, as it was both straightforward and essential for user comfort. I defined the body and body.dark styles in CSS, then created a smooth transition animation to prevent jarring visual changes. The toggle button was positioned in the top-right corner for intuitive access. While I haven't finalized the color palette yet, this foundational work will make future styling adjustments easier.

The page layout was divided into two main sections: a left panel containing the search form and input field, and a right panel for displaying selected films. After styling these components, I faced the challenge of implementing the film search functionality. Since browsers restrict direct CSV access for security reasons, I developed a Python/Flask backend solution. This backend processes search queries in real-time, accesses my temporary CSV database of about 20 sample film titles, and returns matching results to the frontend.

Through JavaScript functions, I established communication between the frontend and Flask backend. The system now successfully sends queries, receives responses, and displays matching films in a dropdown menu. When users click a result, it's added to the selection panel.

While this first version meets basic requirements, several improvements remain:

    + Adding keyboard submission (Enter key support)
    + Enhancing overall visual design
